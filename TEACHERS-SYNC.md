# Синхронизация сотрудников с АИС

Скрипт: `scripts/sync-teachers.mjs` (заменил `migrate-teachers-full.js`).
Тесты: `scripts/sync-teachers.test.mjs`, фикстуры — `scripts/fixtures/`.

---

## Что синхронизируется

Источник — портал школы: `https://school1298.ru/portal/workers/workersPS-no.json`
(можно указать файл: `--source ./fixtures/teachers.json`).

| Данные | Поведение |
|---|---|
| Новый сотрудник | создаётся, `syncEnabled = true`, роль **«Сотрудник»** (`EMPLOYEE`) |
| Классное руководство | создаются классы в каноническом виде (`5-А` → `5А`), выдаётся `CLASS_TEACHER` |
| ФИО изменилось | обновляется в нашей БД |
| Email изменился | обновляется, если новый адрес не занят другим сотрудником (иначе — ошибка в отчёте) |
| Классы изменились | новый класс закрепляется, старый освобождается (`ownerId = null`) |
| Пропал из источника | **архивируется** (`archived = true`, `archivedAt`), классы освобождаются, роль классного руководителя снимается, аккаунт и история остаются. **Вход закрыт**, сессия аннулируется |
| Вернулся | восстанавливается из архива, классы и роль возвращаются, **вход снова работает** |
| Класс заявлен двумя | владелец не меняется, конфликт пишется в отчёт |
| Email занят в источнике | запись пропускается (дубль), остальные обрабатываются |

## Кого синхронизация не трогает

- **Охрана** (роль `SECURITY`) — полностью пропускается: ни роли, ни классы, ни архив.
- **Ручные сотрудники** (`syncEnabled = false`) — их ФИО, почта, роли и классы не меняются.
  Флаг ставится при ручном создании в админке (по умолчанию выключен) и переключается
  в карточке сотрудника.
- Классы, закреплённые за ручным сотрудником или охраной, не отбираются.

## Правила

- Первый импорт: **всем** созданным сотрудникам — `EMPLOYEE`; `CLASS_TEACHER` — только тем,
  у кого в источнике есть класс.
- `TEACHER` синхронизация не выдаёт и снимает у синхронизируемых: учитель без класса
  остаётся «Сотрудником».
- Роли `ADMIN`, `METHODIST` и прочие синхронизация не трогает.
- Классы хранятся в одном формате: `5А`, без дефиса и пробелов (`5-А`, `5 а` → `5А`).
  На `Class.name` добавлен уникальный индекс. Нормализация применяется и к данным АИС
  (ученики, нарушения, ВШУ, доверенности), см. `lib/class-name.ts`.
- Одноразовая нормализация существующих данных: `node scripts/normalize-class-names.mjs --apply`.
- Матчинг: сначала по `externalId` (Id записи в источнике), затем по email.

## Запуск

```bash
# 1. Проверка без записи: покажет, что изменится
node scripts/sync-teachers.mjs

# 2. Отчёт лежит в sync-teachers-report.json

# 3. Применение
node scripts/sync-teachers.mjs --apply

# Опции
--source <url|path>       другой источник
--database-url <url>      другая база (например, ?schema=sync_test)
--report <path>           путь отчёта
--verbose                 подробный лог
```

Перед первым боевым запуском рекомендуется снять дамп БД.

## Отчёт

`sync-teachers-report.json`: режим, время, счётчики (создано/обновлено/восстановлено/
архивировано/пропущено), классы (создано/закреплено/перезакреплено/освобождено/конфликты),
роли, `errors`, `warnings`, `details` — по каждому изменению.

## Тесты

Тесты работают на отдельной схеме PostgreSQL, чтобы не трогать рабочие данные.

```bash
# один раз создать схему
DATABASE_URL="postgresql://.../el_service?schema=sync_test" npx prisma db push

# прогнать сценарии
SYNC_TEST_DATABASE_URL="postgresql://.../el_service?schema=sync_test" node scripts/sync-teachers.test.mjs
```

Покрыто: первый импорт, идемпотентность, смена ФИО/почты/классов, новый сотрудник,
увольнение и архив, возврат, охрана, ручные сотрудники, конфликт классов,
dry-run, занятый email — 55 проверок.

## Доступ архивных сотрудников

- Вход закрыт: `authorize` и `signIn` отклоняют архивных, а `jwt`/`session` аннулируют
  уже выданную сессию при следующем запросе (API отвечает 401).
- Возврат: синхронизация снимает архив (`archived = false`), после чего человек снова
  входит обычным способом. Ничего вручную разблокировать не нужно.

## Нормализация классов

- Хелпер: `lib/class-name.ts` (`normalizeClassName`, `parseClassName`).
- Группировка учеников из MySQL и API классов сравнивают классы по каноническому имени.
- При сохранении нарушения `className` нормализуется.
- Скрипт `scripts/normalize-class-names.mjs` переименовывает старые классы, сливает дубли
  (переносит посещаемость, пропуска, ВШУ, заметки, новости) и чистит `className` в
  нарушениях, ВШУ, доверенностях и самовыходах. По умолчанию — проверка, `--apply` — запись.

## Ограничения

- Источник не различает педагогический и непедагогический состав: все получают
  `EMPLOYEE`; категории вроде «учитель» выдаются вручную.
- Дубли ФИО не различаются: ключ — `externalId` и email.
- Если у сотрудника нет валидного email в источнике, он пропускается (в отчёте видно).
- Архивированный сотрудник не блокируется на входе: аккаунт остаётся рабочим,
  история доступна. Блокировку входа можно добавить отдельным решением.
