# Синхронизация сотрудников на боевой базе: порядок работ

Коротко: **дамп → миграция → нормализация классов → «усыновление» текущих сотрудников →
проверочный прогон → запись**. Ниже — по шагам.

---

## 0. Что понадобится

- Доступ к продовой PostgreSQL и возможность выполнить `pg_dump`/`psql`.
- Окно на 10–20 минут (синхронизация 300 сотрудников занимает секунды, но миграция
  и первый импорт меняют данные).
- Переменные окружения: `DATABASE_URL`, `NEXTAUTH_SECRET`; `DEV_LOGIN` **не** должен
  быть `true`.

---

## 1. Дамп базы (обязательно)

```bash
pg_dump "$DATABASE_URL" -Fc -f backup_before_teachers_sync_$(date +%F_%H%M).dump
ls -lh backup_before_teachers_sync_*.dump
```

Дамп — это план отката. Без него дальше не идти.

---

## 2. Деплой кода

```bash
git checkout el-service-teachers-sync     # или смержить в main
pnpm install
pnpm build
# перезапустить процесс приложения (pm2/systemd/docker)
```

Приложение можно перезапускать до миграции: новые поля читаются только там,
где они есть, но синхронизацию ещё не запускаем.

---

## 3. Миграция схемы

Нужны четыре поля у `User` (`externalId`, `syncEnabled`, `archived`, `archivedAt`),
nullable `Class.ownerId` и два уникальных индекса.

### Вариант А (если классы уже уникальны)

```bash
pnpm db:push
```

`prisma db push` добавит колонки и индексы. Если в `Class` есть дубли имён —
он остановится на предупреждении: переходите к варианту Б.

### Вариант Б (рекомендуется)

Выполните **часть 1** из `scripts/sql/teachers-sync-migration.sql` — только колонки
и nullable `ownerId`, **без** уникальных индексов:

```bash
psql "$DATABASE_URL" -c '
  ALTER TABLE "User" ADD COLUMN IF NOT EXISTS "externalId" TEXT;
  ALTER TABLE "User" ADD COLUMN IF NOT EXISTS "syncEnabled" BOOLEAN NOT NULL DEFAULT false;
  ALTER TABLE "User" ADD COLUMN IF NOT EXISTS "archived" BOOLEAN NOT NULL DEFAULT false;
  ALTER TABLE "User" ADD COLUMN IF NOT EXISTS "archivedAt" TIMESTAMP(3);
  ALTER TABLE "Class" ALTER COLUMN "ownerId" DROP NOT NULL;
'
```

Дальше — шаг 4 (нормализация), затем **часть 2**:

```bash
psql "$DATABASE_URL" -c '
  CREATE UNIQUE INDEX IF NOT EXISTS "User_externalId_key" ON "User"("externalId");
  CREATE UNIQUE INDEX IF NOT EXISTS "Class_name_key" ON "Class"("name");
'
```

## 4. Нормализация классов «5-А» → «5А»

Сначала проверка (ничего не пишет):

```bash
node scripts/normalize-class-names.mjs
```

Посмотрите цифры: сколько классов будет переименовано и слито, сколько нарушений/ВШУ/
доверенностей поправится. Затем запись:

```bash
node scripts/normalize-class-names.mjs --apply
```

Что делает: переименовывает классы, **сливает дубли** (переносит посещаемость, пропуска,
ВШУ, заметки, новости, шаринги) и приводит `className` в нарушениях, ВШУ, доверенностях
и самовыходах к виду без дефиса.

Проверка после:

```sql
SELECT name, COUNT(*) FROM "Class" GROUP BY name HAVING COUNT(*) > 1;  -- пусто
SELECT DISTINCT "className" FROM "Violation" WHERE "className" LIKE '%-%'; -- пусто
```

## 5. «Усыновление» существующих сотрудников (важно)

Старый импорт создал пользователей без флага синхронизации, поэтому по умолчанию
синхронизация считает их **ручными** и не трогает. Для первого запуска есть режим
`--adopt`: он находит сотрудника по email/`externalId` и включает ему `syncEnabled`,
после чего ФИО, почта и классы начинают обновляться из источника.

Сначала **проверка**:

```bash
node scripts/sync-teachers.mjs --adopt
```

В отчёте смотрите:

- `взято под синхронизацию` — сколько существующих сотрудников подключится;
- `создано пользователей` — если это большое число, значит email в базе не совпадает
  с источником и синхронизация создаст дубли;
- `пропущено ручных` — кого не удалось сопоставить.

Если `создано` неожиданно много — не применяйте. Сверьте отчёт `sync-teachers-report.json`
и либо поправьте email в базе под источник, либо сопоставьте вручную. После сверки
повторите.

Применение:

```bash
node scripts/sync-teachers.mjs --adopt --apply
```

Эквивалент через npm: `pnpm sync:teachers:adopt`.

Дальше можно пользоваться страницей **`/admin/sync`** («Проверить» / «Синхронизировать»).

---

## 6. Что произойдёт с данными

- Новые сотрудники из источника появятся с ролью «Сотрудник»; у кого есть класс —
  класс и роль «Классный руководитель».
- ФИО и email обновятся; при конфликте email (занят другим) — ошибка в отчёте,
  старый адрес остаётся.
- Классы передадутся тем, кто указан в источнике. Классы **охраны** не отбираются.
- Сотрудники, которых нет в источнике, уйдут в **архив** (вход закрыт, история сохранена).
- Охрана (SECURITY) и ручные сотрудники не меняются (кроме `--adopt`).
- Администраторы (`ADMIN`) не удаляются и не архивируются автоматически, если они
  есть в источнике; если админа нет в источнике и он `syncEnabled=true` — он уйдёт
  в архив. Проверьте это заранее.

---

## 7. Проверка после первого запуска

1. Вход администратора и любого учителя — работает.
2. `/admin/classes` — у классов есть классные руководители, ученики на месте.
3. `/admin/violations` — старые нарушения видны, фильтр по классу работает.
4. Учитель на `/my-class` видит свой класс и учеников.
5. Архивированный сотрудник (если появился) не входит в систему.
6. `sync-teachers-report.json` — нет ошибок, предупреждения понятны.

---

## 8. Регулярная синхронизация

- вручную: `/admin/sync` → «Проверить», затем «Синхронизировать»;
- по расписанию (cron, от пользователя приложения):

```bash
0 6 * * * cd /path/to/app && node scripts/sync-teachers.mjs --apply --report /var/log/teachers-sync.json
```

Отчёт храните: по нему видно, кого архивировали и какие классы передали.

---

## 9. Откат

1. Остановить синхронизацию (cron/кнопку).
2. Восстановить дамп:

```bash
pg_restore --clean --if-exists -d "$DATABASE_URL" backup_before_teachers_sync_*.dump
```

3. Откатить код на предыдущий коммит и перезапустить приложение.

Поля синхронизации в откате не нужны — они не мешают старой версии.

## Частые вопросы

**Почему у части сотрудников «ручной»?** `syncEnabled=false` — так создаются вручную
и так пришли из старого импорта. Включить можно в карточке сотрудника или первым
запуском с `--adopt`.

**Сотрудник уволился, но в источнике ещё есть?** Он останется активным: источник — истина.
Уберите его из внешней системы или снимите флаг синхронизации.

**Учитель сменил фамилию/почту?** Обновится автоматически; при занятом email будет
ошибка в отчёте.

**Класс перешёл другому учителю?** Класс перезакрепится, старый владелец его потеряет,
роль «Классный руководитель» снимется, если классов не осталось.

**Нужно не отбирать классы у ручных сотрудников?** Запускайте с `--keep-manual-classes`.
