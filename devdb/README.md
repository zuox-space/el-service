# Локальные моковые БД (devdb)

Здесь лежит всё для того, чтобы запускать приложение и проверять правки локально, **не касаясь
рабочей базы школы**.

## Зачем так

На машине нет «своего» PostgreSQL или MySQL, а единственный установленный PostgreSQL — это
встроенная база КОМПАС-3D (`C:\Program Files\ASCON\...\LocalBase`, порт 5433). Трогать её нельзя,
прав администратора для установки служб тоже нет. Поэтому в `devdb/` скачиваются **переносимые**
бинарники, а данные лежат в каталогах внутри `devdb/data`. Ничего не устанавливается в систему,
службы не создаются, реестр не меняется.

Две базы — потому что приложение работает с двумя хранилищами:

| База | Что хранит | Порт | Доступ |
|---|---|---|---|
| PostgreSQL 18 | данные приложения: сотрудники, роли, классы, посещаемость, пропуска, нарушения, ВШУ, доверенности (Prisma) | 55432 | `postgres` / `postgres`, база `el_service` |
| MariaDB 11.4 | внешняя база АИС со списком учеников (таблица `students`, читается через mysql2) | 33306 | `root` без пароля, база `school_ais` |

## Быстрый старт

```bash
node scripts/devdb.mjs status          # проверить, что запущено
node scripts/devdb.mjs start           # запустить базы
node scripts/devdb-seed.mjs --fresh    # наполнить тестовыми данными
node scripts/devdb-test.mjs            # сквозная проверка API (нужен запущенный сервер)
```

Через npm-скрипты:

```bash
npm run devdb:status
npm run devdb:start
npm run devdb:stop
npm run devdb:seed -- --fresh
npm run devdb:test
```

Все команды управления: `bootstrap | download | extract | init | start | stop | status | reset | env | dbs`.

## Запуск приложения

Файл `.env.local` уже создан и указывает на моковые базы (он в `.gitignore`).

```bash
# обычный dev-сервер (как в проекте) — HTTPS с самоподписанным сертификатом
npm run dev

# либо по HTTP, удобнее для скриптов и тестов
node node_modules/next/dist/bin/next dev -p 3000
```

- 8 сотрудников, 4 роли, 12 классов (1А…10А), 268 учеников в базе АИС;
- ~542 записи посещаемости, 126 пропусков, 25 самовыходов, 27 доверенностей, 14 записей ВШУ;

одинаковый. Даты считаются от текущего дня назад, последние ~10 недель.

## Сквозной тест `devdb-test.mjs`

Проверяет то, что нельзя проверить статически:

1. вход локальным провайдером и получение ролей в сессии;
2. `/api/violations` отдаёт `total`, равный числу записей в базе (а не размеру страницы);
3. обход всех страниц собирает все записи без пропусков и дублей;
4. серверные фильтры по типу, классу и поиску согласованы с базой;
5. статистика за «сегодня» совпадает с базой (проверка границ дат);
6. без авторизации API отвечает 401.

## Особенности Windows, из-за которых всё так устроено

1. **Кириллица в пути.** Проект лежит в `OneDrive\Документы`, а PostgreSQL на Windows падает на
   таком пути с `invalid byte sequence for encoding "UTF8"`. Поэтому и каталог данных, и копии
   бинарников адресуются через короткое 8.3-имя (`C:\Users\kiryx\OneDrive\7496~1\...`), а дочерние
   процессы запускаются из ASCII-каталога. Короткое имя определяется один раз командой
   `node scripts/devdb.mjs bootstrap` и сохраняется в `devdb/.ascii-root`.
   **Если проект перенесёте — удалите `devdb/.ascii-root` и выполните `bootstrap` снова.**
2. **Переменная `PGDATA` в системе.** Она указывает на базу КОМПАС-3D с кириллическим путём и
   наследуется дочерними процессами `initdb`. Скрипты её вычищают перед запуском.
3. **PowerShell не скачивает файлы** на этой машине (`Invoke-WebRequest` обрывает соединение),
   поэтому загрузка сделана через `fetch` в Node.
4. **`mysqld` падает на системном TEMP** (`InnoDB: Unable to create temporary file`), поэтому
   `--tmpdir` задан явно внутри `devdb/data/mysqltmp`.

## Если что-то пошло не так

```bash
node scripts/devdb.mjs status      # что запущено
node scripts/devdb.mjs stop
node scripts/devdb.mjs start
node scripts/devdb.mjs reset       # УДАЛИТ все локальные данные и создаст заново
node scripts/devdb.mjs init        # создать базы и применить схему Prisma
```

Логи: `devdb/logs/postgres.log`, `devdb/logs/mariadb.log`.

## Что не является рабочими данными

`devdb/` — только для разработки. Никакие команды отсюда не трогают рабочую базу школы:
подключение задаётся файлом `.env.local`, а он локальный и в `.gitignore`.
