# Ключница

Модуль учёта ключей, перенесённый из `keys-app` и встроенный в приложение.
Пользователи — наши (`User`), отдельной авторизации у ключей нет.

## Что умеет

- здания и ключи (номер, кабинет, этаж, свободен/выдан, на руках у сотрудника);
- заявки: **выдать**, **сдать**, **передать** коллеге;
- подтверждение: выдачу/сдачу подтверждает охрана или администратор ключей,
  передачу — получатель;
- журнал операций и история заявок;
- избранные ключи;
- ограниченный доступ к отдельным ключам (только выбранным сотрудникам);
- импорт ключей из CSV;
- SSE-обновления: новые заявки и изменения приходят сразу.

## Планшет охраны

Отдельный контур для планшета:

- `/guard` — страница охраны, `/guard/login` — свой вход по логину и паролю;
- логин/пароль задаются в `GUARD_LOGIN` / `GUARD_PASSWORD`, cookie подписана
  `GUARD_SESSION_SECRET` (fallback — `NEXTAUTH_SECRET`);
- Яндекс и NextAuth не используются;
- на планшете один экран с табами: **Заявки** (выдача/сдача слева, история
  справа), **Ключи**, **Пропуска** (активные и ушедшие, отмена выхода,
  алфавит и поиск), **Самовыходы** (поиск по имени ребёнка и алфавит,
  только 1–6 классы);
  списки прокручиваются внутри панелей, страница не скроллится; выбор здания — в шапке пульта,
  хранится в `localStorage` (`guard-building-id`) и фильтрует ключи и историю;
- подтверждения пишутся в журнал от системного пользователя «Охрана».

API планшета: `/api/guard/login`, `/api/guard/state`, `/api/guard/events`,
`/api/guard/history`, `/api/guard/requests/[id]/decision`,
`/api/guard/passes/[id]/use`.

Доступ к администрированию ключей (`/admin/keys`, здания, история) — только у
роли с разделом `keysAdmin`.

## Доступы

Два раздела в реестре (`lib/access/registry.ts`):

| Раздел | Что открывает | По умолчанию |
|---|---|---|
| `keys` | `/keys`, заявки, мои ключи, история | все роли (кроме ADMIN — у него всё) |
| `keysAdmin` | `/admin/keys`: ключи, здания, заявки, журнал, права | только ADMIN |

- Доступ к пульту (`keys`) выдаётся ролям/сотрудникам как обычный раздел.
- Администрирование (`keysAdmin`) — отдельный раздел; его можно выдать роли
  в «Администрирование → Роли и доступы», не давая доступ к остальной админке.
- Подтверждать заявки могут `SECURITY` и обладатели `keysAdmin`.
- Охрана не создаёт заявки — только обрабатывает.

Если у роли уже настроен непустой `defaultSections`, добавьте в него `keys`:

```bash
node scripts/keys-role-access.mjs          # проверка
node scripts/keys-role-access.mjs --apply  # запись
```

## Интерфейс

Экраны повторяют keys-app:

- **Портал** — карточка «Ключи».
- **Слева снизу** — кнопка с ключом, раскрывается списком со стрелками:
  «Взять», «Сдать», «Передать» и «Принять» (если есть входящая передача).
  Каждый пункт открывает свою модалку; передача — с поиском коллеги.
- **`/keys` — кабинет сотрудника**: вкладки «Ключи», «Мои ключи», «Избранное»,
  «Заявки»; мультивыбор, запрос, сдача, передача, отмена. История ключа —
  последние 5 операций со статусами, без фильтров; фильтр по зданию запоминается
  в `localStorage` (`keys-building-id`).
- **`/keys` для охраны — пульт**: вкладки «Выдача», «Не сдали», «Ключи», «Журнал»;
  подтверждение выдачи/сдачи, группировка «не сдали» по держателям, подсветка
  после 18:00, журнал.
- **`/admin/keys`** — таблица ключей: фильтры, создание, импорт CSV; история
  и права открываются справа в модалках, в правах — поиск по ФИО;
- **`/admin/keys/buildings`** — здания.
- История и права открываются справа в разделе «Ключи». История ключа —
  широкая правая панель без фильтров: кто запросил, кому передали,
  кто подтвердил/отменил и когда. В правах — поиск по ФИО.

## Данные

Новые таблицы, существующие не меняются:

- `KeyBuilding` — здания;
- `KeyItem` — ключи (`status`, `holderId`, `accessScope`);
- `KeyPermission` — доступ к ограниченным ключам;
- `KeyFavorite` — избранное;
- `KeyRequest` / `KeyRequestItem` — заявки и их ключи;
- `KeyActivity` — журнал операций.

Схема применяется обычным `prisma db push` (в Dokploy — `RUN_MIGRATIONS=true`
на первом деплое). Данные ключей начинаются с нуля: здания и ключи добавляются
в `/admin/keys` или импортом CSV.

### Импорт CSV

Формат (разделитель `;`, `,` или таб):

```
building;building_address;room_number;room_name;floor
Основной корпус;ул. Школьная, 1;101;Кабинет математики;1
```

Импорт идемпотентен: существующие ключи обновляются, новые создаются.

## API

| Метод | Путь | Доступ |
|---|---|---|
| GET | `/api/keys/state` | `keys` или `keysAdmin` |
| GET | `/api/keys/events` | SSE, `keys` или `keysAdmin` |
| POST | `/api/keys/requests` | `keys` |
| POST | `/api/keys/requests/[id]/decision` | `keys` + проверка роли |
| GET | `/api/keys/history` | `keys` или `keysAdmin` |
| GET | `/api/keys/users` | `keys` или `keysAdmin` |
| POST | `/api/keys/favorites` | `keys` |
| GET/POST | `/api/keys` | `keysAdmin` |
| PATCH/DELETE | `/api/keys/[id]` | `keysAdmin` |
| GET/PUT | `/api/keys/[id]/permissions` | `keysAdmin` |
| GET/POST | `/api/keys/buildings` | `keysAdmin` |
| PATCH/DELETE | `/api/keys/buildings/[id]` | `keysAdmin` |
| POST | `/api/keys/import` | `keysAdmin` |

## Проверка

```bash
node scripts/keys-test.mjs http://localhost:3000
```

Тест создаёт временное здание и ключи, проходит выдать → подтвердить → сдать →
передать → ограничить доступ, проверяет страницы и SSE, затем удаляет за собой.

## Ограничения

- SSE работает в пределах одного процесса: в Dokploy приложение запускается
  одним контейнером. При нескольких репликах понадобится общая шина (Redis).
- Подтверждение — только охрана/администратор ключей; массовых операций нет.
